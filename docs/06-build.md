# 第 6 章：建構應用程式

本章你要用 Kiro 的 agentic 能力，把 Flappy Kiro 遊戲建構出來。

> 每個任務的實作時間取決於複雜度、Kiro 在實作過程中迭代的次數，以及執行產出程式碼所花的時間。

---

## 6.1 開始建構流程

1. 開啟位於 `.kiro/specs` 資料夾的 `tasks.md`

   這份文件包含建構應用程式所需的循序任務清單。每個任務包含：

   - 一個帶編號的標題
   - 一份詳細指示的項目清單
   - 該任務所對應的需求引用清單

2. 點任務旁的 **ϟ Start task** 圖示開始執行

---

## 6.2 監看與控制任務進度

Kiro 開始處理任務後，描述會變成 **⥀ Task in progress**。點 **View changes** 可在 Kiro chat 視窗中顯示任務與子任務的進度。

> 完成每個任務的過程中，Kiro 會自行檢查是否有問題，並反覆迭代以排除錯誤。

你可能需要授權 Kiro 執行相關指令：

- 要允許 Kiro 執行該指令，選 **Accept**
- 要在本次 session 剩餘時間都允許該指令，選 **Trust command and accept**

你可以選擇信任「完整指令（含特定參數）」，或是信任「基礎指令」讓它能帶任意參數執行。

---

## 6.3 排除問題

### Kiro 卡住了

如果 Kiro 在某個任務上似乎停滯，點該任務的頁籤，請 Kiro 回報進度並指示它在可行的情況下繼續。

```
檢視你目前的進度，如果可以就繼續往下做。
```

```
你卡住了嗎？
```

### 任務失敗

如果任務失敗，點 **Chat with Kiro to fix** 請 Kiro 協助解決並完成任務。在 chat 中與 Kiro 一起診斷並修正問題，然後請它重新執行該任務。

---

## 6.4 檢視完成的任務

任務完成後，Kiro 會在 chat 視窗中描述實作摘要。

對實作結果滿意後，就可以進行下一個任務。

> **提示**：你可以**排隊**多個任務 — 選取多個任務，Kiro 會完成第一個後自動接續下一個。

> **提示**：除了一次執行一個任務，你也可以**一次執行整份計畫**。Kiro 會判斷任務之間的依賴關係，並讓彼此獨立的任務並行執行，藉此加快建構速度。會寫入相同檔案的任務絕不會並行，而執行前置設定工作的任務會先跑。
>
> 可在 Kiro panel 中監看任務佇列。

---

## 6.5 （選配）啟用 property-based test

在執行階段，Kiro 會把先前產生的 property-based test（PBT）案例實際跑在你的實作上。

PBT 預設是選配的。要啟用這些測試，在 `tasks.md` 中對相關測試選擇 **Make task required**。
