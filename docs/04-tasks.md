# 第 4 章：產生實作任務

本章你要產出實作計畫，寫在 `tasks.md` 中。

`tasks.md` 是你把實作拆解成離散、可執行步驟的地方，每個步驟都有清楚的依賴關係與驗收條件。這份文件提供一份詳細的實作計畫，其中的任務可被追蹤，並且可以單獨執行或一次全部執行。

```
tasks.md → 滿意？ ──否──→ 編輯 / 要求修改 ─┐
             │                          │
             是                         └─→ 回到 tasks.md
             ↓
            完成
```

---

## 4.1 回答 Kiro 的問題

產生 `tasks.md` 的過程中，Kiro 可能需要你協助釐清一些問題。

在 Kiro panel 中檢視這些問題，並選擇合適的答案。

## 4.2 精修實作任務

流程你已經熟悉了 — 檢視、要求調整、再檢視。

以下範例 prompt 展示一個有用的模式：**要求 Kiro 產生額外的規格文件**，把設計決策固定下來，避免實作時每次都要重新猜測。

```
產生 `game-config.json`，包含完整的物理參數：
重力 (800 px/s²)、跳躍速度 (-300 px/s)、牆面移動速度 (120 px/s)、
缺口大小 (140px)、牆面間距 (350px)。
```

```
建立 `ghosty-sprites.md`，包含詳細的角色規格：
sprite 尺寸 (32x32px)、idle / flap / death 三種狀態的動畫影格、
hitbox 半徑 (12px)。
```

```
建立 `audio-assets.md`，包含音效設計規格：
拍翅音（短促的 whoosh，0.1 秒）、計分音（悅耳的鈴聲，0.2 秒）、
碰撞音（低沉的撞擊聲，0.3 秒）。
```

```
產生 `ui-mockups.md`，包含介面設計：
主選單版面（含開始遊戲與最高分按鈕）、
遊戲中的 HUD（顯示當前分數）、
遊戲結束畫面（含最終分數與重新開始選項）。
```

> **關於 `audio-assets.md`**：本課程的 starter kit **已經提供**做好的音效（`jump.wav`、`score.wav`、`game_over.wav`、`bgm.wav`），所以你不需要真的去製作音效。這份文件的價值在於記錄「每個音效在什麼時機播放」，你可以改成請 Kiro 描述現有素材的使用時機：
>
> ```
> 建立 `audio-assets.md`，記錄 assets/ 中現有音效的使用時機：
> jump.wav 在拍翅時、score.wav 在通過水管得分時、
> game_over.wav 在碰撞時、bgm.wav 在遊玩中循環播放。
> ```

## 4.3 完成任務清單

把實作計畫定稿。別忘了 commit 你的變更！

> **提示**：試著請 Kiro 幫你 commit！

```
產生 commit message 並提交到 Git。
```

```
把變更提交到 Git。檢視這些變更，產生一個 git commit message 說明改了什麼。
註明這是「產生實作任務」階段的結束。
```
